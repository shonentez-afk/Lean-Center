# LC5.3 — устранение замечаний проверки LC5.2
Исходная проверенная LC5.2: commit 097629fb257fe3e11bd3d5c4780a160929a45167, CI 45735069573; 80 JS, 5 Python, полные browser smoke. Вход: приватный ZIP отчёта проверки, не загружать его в GitHub. Ветка feature/lc5.3-review-fixes, v13 без новой миграции. LC4.4.1 остаётся явно принятой рабочей версией.

## Функциональность
- Восстановлен RC1: предварительный/итоговый локальный анализ до сохранения, по шагам, слабый шаг при наличии отрицательных ответов, первые три рекомендации исходной методики, редактируемая обратная связь, все остальные замечания в чек-листе. Текст обновляется только если ещё пуст или ранее автоматически сформирован; ручная правка не заменяется молча. Незаполненное и исключение без основания не входят в знаменатель.
- Аналогичный инструмент для практики (0/1; заключение остаётся отдельным), самооценки (1–5, не квалификация, приоритеты развития по меньшим уровням), корпоративской и взвешенной оценки СОП; автоматические оценки взвешенного чек-листа не становятся подтверждёнными замечаниями. Сохранённые карточки дают переход к конкретному критерию/мероприятию, общий реестр не дублируется. Прогресс и переход к первому пропущенному вопросу.
- Мобильный L1: очередь до 100 неподтверждённых записей в контексте, статусы pending/exported/accepted. Экспорт не удаляет. На ПК импортировать, принять свои изменения, затем скачать подтверждение по исходному пакету. Оно выдаётся только по принятой базе и совпадению ID/хэша. В мобильном HTML принять подтверждение: сверка ID, SHA-256 и базы, частичное освобождение очереди, сохранение истории и исходных ID при повторной выгрузке. Это локальный файл подтверждения, не цифровая подпись сервера; доверять только полученному с ответственного ПК. Старый HTML не обновляется автоматически: скачать новый; если localStorage из старого файла недоступен, перенести прежний JSON кнопкой восстановления.
- Повторяемость — количество уникальных training_session_id, не число отчётов; отрицательные ответы отдельно, исторические без факта отдельно. Метрика L1 передаёт роль инструктора, период, состояние и подразделение; аналитика передаёт версию, смену и точный критерий/СОП при повторном отклонении.
- Плановый L1: единый предикат UI и ядра, не показывать аннулированные/использованные/старые факты, сообщать причину пустого списка.
- История RC1: поля annulmentReason и annulledAt сохраняются в дополнительном архиве с точным source ID, revision и hash исходного нормализованного факта, в карточке выводится исходное доказательство; для уже импортированных фактов отдельное явное дополнение метаданных, без переписывания оценки. Если только точный журнал type=annul — использовать при совпадении ID и ревизии. Конфликтующие источники не разрешать автоматически. Разбиение до 20 тыс. аудитов и до 20 МиБ входного JSON, до 100 аудитов на подтверждение; история блоками до 1,5 МБ, точные дубли пропускаются, отдельные слишком большие строки обозначаются. Существующий лимит рабочего пакета 5 МБ/2000 событий сохранён: принимать изменения между пакетами. Архивные мероприятия не становятся активными.
- Узкий экран: скрытое меню, явное раскрытие, прежний десктоп. Тема сохраняется в localStorage, если доступен. Встроенный и браузерный возврат внутри сессии; фильтры поддерживаемых реестров и позиция сохраняются в памяти, незавершённые формы не являются автоматически сохранёнными черновиками.

## Проверки
Модульные тесты на анализ, моб. подтверждение из принятой базы, уникальные факты, предикат календаря, историю аннулирования, большие пакеты; browser smoke на локальный анализ, навигацию, 390px, тему и отдельный мобильный файл с частичной квитанцией, 100 записями и повторным экспортом. Проверять CI актуального head; не считать принятым до пользовательского испытания. Реальные мобильные устройства, корпоративский SMB, исходная база RC1 и реальные финансовые данные не проверены; старые версии не переписывать.
