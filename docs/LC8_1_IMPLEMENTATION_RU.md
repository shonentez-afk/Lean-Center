# LC8.1 — единая спецификация и реализация пользователей Центра TWI

## Принятые требования
- Один каталог сотрудников person, существующий business_role и role_assignment. Серверные политики и гранты привязаны к их ID; нет второго каталога. Производственная роль или импорт сами по себе не выдают доступ.
- Первый администратор: логин admin (настраиваемый); начальный пароль через LC_BOOTSTRAP_ADMIN_PASSWORD. Нет заводского пароля. Создаётся один раз, сохраняется после обновлений. Отсутствующее/повреждённое ранее инициализированное хранилище не создаёт новую учётную запись. Администратор не обязан иметь фиктивную карточку сотрудника.
- Логин пользователя — рабочая почта или индивидуальный логин. Администратор создаёт аккаунт из каталога и выдаёт индивидуальный пароль вручную либо с безопасной генерацией. На испытаниях сразу вход без обязательной смены. Сброс и смена пароля (самостоятельно и администратором), приглашения, восстановление по почте — отключены в UI и API. Сохраняем модель credential_revision и stable account_id для будущего включения. Пароли хранятся только как salted hash, не в журналах/клиентской базе.
- Администратор: учётные записи, роли, права, системные настройки; дополнительно оперативный профиль управляющего. Управляющий: все рабочие модули своего предприятия, включая СОП, обучение, матрицы, аудиты, задачи, календарь, экономику, доплаты, аналитику, отчёты и разрешённый экспорт; без системных прав, паролей, выдачи доступов, резервирования и секретов. Специальные решения требуют отдельного действующего полномочия и назначения. Директор, ОТ, главный инженер, ВТ, руководители подразделений, инструкторы, наставники, разработчики, HR, аудиторы, сотрудники, наблюдатели используют тот же справочник ролей с несколькими назначениями.

Состояние сотрудника, срока роли и занятости, отзыв гранта и ревизия политики проверяются при запросе. Перевод закрывает прежний грант. ## Первый запуск отдельного QA (только после тестов)
Новая пустая (не существующая) папка внутри отдельного тестового тома, не /data/lean-center-pilot. Установить LC81_QA=1, LC81_INIT=1, LC81_DATA_DIR=абсолютный путь новой папки, LC81_ORIGIN=точный HTTPS origin тестового портала, LC_BOOTSTRAP_ADMIN_LOGIN=admin и секрет LC_BOOTSTRAP_ADMIN_PASSWORD (12–128 байт, уникальный, не корпоративный). Запуск node server/lc81-main.mjs за HTTPS reverse proxy. Не переносить LC_PILOT_USERS/LC_PILOT_DEMO=1, не использовать live volume. После успешного первого входа убрать LC81_INIT и секрет и проверить перезапуск. Не удалять writer.lock при работающем процессе. Данные не выставлять на публичную эксплуатацию. Не переключать Amvera на эту ветку: действующий amvera.yml всё ещё относится к LC7.4.6.

## Дальнейшая реализация
Пакет LC8.1 продолжать как единую версию, без переключения работающего портала на промежуточные контуры. Следующие блоки внутри него: покрытие всех сущностей и команд, безопасная миграция копии и резервирование, интеграция всех существующих экранов с серверной политикой, полный регресс пользователей/областей/полномочий и всех функций. Затем отдельные LC8.2/3/4 используют готовый общий контур. Решения по корпоративному размещению, электронной подписи, персональным данным, почте и MFA — до реального запуска.
