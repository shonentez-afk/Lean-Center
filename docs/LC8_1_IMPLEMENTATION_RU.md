Не даёт права проверки/утверждения. Старые сохранённые политики не получают новые permissions автоматически; новые назначения требуют явного подтверждения. Первичный админ на QA не выполняет персональные решения до отдельной реализации связи с сотрудником.

CLI (остановленный синтетический backup, не живой том): LC81_QA=1 и bootstrap-секрет, затем node server/lc81-maintenance.mjs migrate-copy ABS_SOURCE ABS_NEW_TARGET SITE_ID ADMIN_ROLE_ID MANAGER_ROLE_ID. Значение new допустимо вместо ID только при отсутствии совпадающей роли. Backup/restore-new: node server/lc81-maintenance.mjs backup|restore-new ABS_SOURCE ABS_NEW_TARGET. Оба пути — отдельные папки, целевая не существует, родитель существует. Не переносить реальные данные, не переключать amvera.yml. Секреты в командной строке не задавать; хэши и вложения защищённого бэкапа также требуют закрытого хранения. Сессии не сохраняются при восстановлении.

Тесты нового кандидата включают сравнение всех старых доменных таблиц и байтов исходников на синтетической базе, доступ управляющего через существующую роль, персональные права и выполнение задачи, сохранение аккаунтов и результатов при backup/restore, отказ при повреждении вложения. До завершения LC8.1 остаются миграция/подключение полного интерфейса, все остальные бизнес-команды, полноценная работа с файлами, матрицы, аналитика, редактирование, администрирование нескольких аккаунтов администраторов, привязка bootstrap к сотруднику, отдельные области смен/операций и сверка регламента. # LC8.1 — единая спецификация и реализация пользователей Центра TWI

27.11.2026. Эта спецификация консолидирует принятые решения владельца и имеет приоритет над ранними вариантами в документах LC8.1. Не является разрешением на перенос действующего портала.

## Принятые требования
- Один каталог сотрудников person, существующий business_role и role_assignment. Серверные политики и гранты привязаны к их ID; нет второго каталога. Производственная роль или импорт сами по себе не выдают доступ.
- Первый администратор: логин admin (настраиваемый); начальный пароль через LC_BOOTSTRAP_ADMIN_PASSWORD. Нет заводского пароля. Создаётся один раз, сохраняется после обновлений. Отсутствующее/повреждённое ранее инициализированное хранилище не создаёт новую учётную запись. Администратор не обязан иметь фиктивную карточку сотрудника.
- Логин пользователя — рабочая почта или индивидуальный логин. Администратор создаёт аккаунт из каталога и выдаёт индивидуальный пароль вручную либо с безопасной генерацией. На испытаниях сразу вход без обязательной смены. Сброс и смена пароля (самостоятельно и администратором), приглашения, восстановление по почте — отключены в UI и API. Сохраняем модель credential_revision и stable account_id для будущего включения. Пароли хранятся только как salted hash, не в журналах/клиентской базе.
- Администратор: учётные записи, роли, права, системные настройки; дополнительно оперативный профиль управляющего. Управляющий: все рабочие модули своего предприятия, включая СОП, обучение, матрицы, аудиты, задачи, календарь, экономику, доплаты, аналитику, отчёты и разрешённый экспорт; без системных прав, паролей, выдачи доступов, резервирования и секретов. Специальные решения требуют отдельного действующего полномочия и назначения. Директор, ОТ, главный инженер, ВТ, руководители подразделений, инструкторы, наставники, разработчики, HR, аудиторы, сотрудники, наблюдатели используют тот же справочник ролей с несколькими назначениями.
- RBAC + область + связь с конкретным объектом + доменные условия. Проверки на сервере, default deny, одна полная подходящая связка роль/область/действие, нет wildcard. Состояние сотрудника, срока роли и занятости, отзыв гранта и ревизия политики проверяются при запросе. Перевод закрывает прежний грант. Не разрешать передавать полную SQLite или произвольные пакеты в secure mode.
- СОП: три обязательных согласования руководителем ОТ, главным инженером и ВТ, затем отдельное утверждение директором, после этого ввод в действие. Не выдавать администратору или управляющему право решения за другое лицо. Привязка к ревизии и хэшу, история и серверный actor/time. Порядок/замещение по локальному регламенту; отдельный стандарт оформления СОП ещё не найден. Старый approved нельзя автоматически считать утверждением директором. Действующая версия сохраняется до ввода новой.
- Уведомления LC8.2, согласования LC8.3, email LC8.4 используют те же account/person/role/scope. Никаких реальных рассылок на QA. Старый AI и дизайн/функции LC7.4.6 не менять без согласования.

## Реализованный интегрированный испытательный контур (кандидат)
Файлы server/lc81/* и server/lc81-main.mjs, отдельная точка входа. Не подключены к legacy server/main.mjs или amvera.yml. Единая v17 SQLite с private service schema, одной атомарной записью защищённого checkpoint secure.lc81 и маркером инициализации. SQL.js доменные валидаторы для создания пяти учебных справочников, без второго доменного ядра. Явно созданная учебная площадка, две зарезервированные роли в business_role, единственный защищённый начальный администратор. Существующие рабочие данные не мигрируются, не изменяются; не копировать реальные данные на QA. Системные роли создаются только на чистой учебной базе; сопоставление существующих ролей при миграции предстоит.

Реализованы scrypt, уникальный нормализованный логин, администратор выдаёт/генерирует пароль при создании, ограничение входа, защищённые HttpOnly Secure SameSite cookies, точный Origin и CSRF header, сессии в памяти (перезапуск требует повторного входа), блокировка/разблокировка с отзывом старых сеансов, версионированные разрешения, гранты к существующему назначению роли и текущему назначению сотрудника, self/assigned/unit_tree, отзыв, журнал без секретов, ограниченная панель пользователей и прав, меню по доступным permissions. Администратор не может заблокировать единственного bootstrap, создавать другого администратора или менять защищённые политики. Смена/сброс/регистрация, старые Bearer tokens, /api/v1/snapshot, /api/v1/packages, исходники и полный экспорт отсутствуют. Настройка первого входа проверяется отдельной командой, не запускает legacy режим. Пароль в секрете не публиковать.

## Границы реализации и оставшиеся условия приёмки
Это НЕ полная LC8.1 и не замена существующего интерфейса из 47 страниц. Четыре безопасные read-проекции: минимальные карточки сотрудников, метаданные действующих СОП (не текст/фото), назначения обучения, задачи (связанные задачи — ограничение по владельцу; область связанных сущностей ещё не разрешена). Новые роли могут настраивать только эти четыре разрешения. Управляющий пока читает только реализованные проекции. UI управления справочниками предназначен для синтетических записей. Нет подтверждённого переноса действующей базы, полноценной миграции/восстановления security store, привязки bootstrap к сотруднику, нескольких администраторов, настройки всех видов областей (смены, операции, конкретные объекты), переноса всех экранов, бизнес-команд, полного экспорта, документов/фото, аналитики/ИИ, механизма согласования, уведомлений или почты. QA business clock = UTC, часовой пояс предприятия предстоит явно настроить. Для завершения LC8.1 нужен server-only слой чтения/записи для всех существующих функций, покрытие прав каждого объекта/поля/действия и полный сквозной регресс. Не выдавать готовность по тестам ограниченного контура.

Автоматическая инвентаризация: node tools/lc81-inventory.mjs (реальные navGroups, definitions, DOMAIN_TYPES и sqlite_master; всё не подключённое явно denied). Тесты: tests/lc81-read-policy.test.mjs, tests/lc81-secure-qa.test.mjs, CI плюс прежнее npm test и LC7.4.6 server tests/build. CI ещё не подтверждён на момент фиксации.

## Первый запуск отдельного QA (только после тестов)
Новая пустая (не существующая) папка внутри отдельного тестового тома, не /data/lean-center-pilot. Установить LC81_QA=1, LC81_INIT=1, LC81_DATA_DIR=абсолютный путь новой папки, LC81_ORIGIN=точный HTTPS origin тестового портала, LC_BOOTSTRAP_ADMIN_LOGIN=admin и секрет LC_BOOTSTRAP_ADMIN_PASSWORD (12–128 байт, уникальный, не корпоративный). Запуск node server/lc81-main.mjs за HTTPS reverse proxy. Не переносить LC_PILOT_USERS/LC_PILOT_DEMO=1, не использовать live volume. После успешного первого входа убрать LC81_INIT и секрет и проверить перезапуск. Не удалять writer.lock при работающем процессе. Данные не выставлять на публичную эксплуатацию. Не переключать Amvera на эту ветку: действующий amvera.yml всё ещё относится к LC7.4.6.

## Дальнейшая реализация
Пакет LC8.1 продолжать как единую версию, без переключения работающего портала на промежуточные контуры. Следующие блоки внутри него: покрытие всех сущностей и команд, безопасная миграция копии и резервирование, интеграция всех существующих экранов с серверной политикой, полный регресс пользователей/областей/полномочий и всех функций. Затем отдельные LC8.2/3/4 используют готовый общий контур. Решения по корпоративному размещению, электронной подписи, персональным данным, почте и MFA — до реального запуска.
