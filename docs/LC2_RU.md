# LC2 — единые справочники и импорт XLSX (кандидат)
Дата 25.11.2026. Ветка feature/lc2-master-data. База: принятая LC1.3.
## Справочники
Существующие подразделения, сотрудники, профессии, оборудование, операции, назначения дополнены должностями, сменами, деловыми ролями, назначениями ролей, категориями навыков, навыками и версионированными шкалами. Иерархия предприятия, фильтры активных/архивных/исторических записей, просмотр назначений и ролей сотрудника. Сотрудник имеет одну запись с табельным номером; несколько разных ролей допустимы одновременно; роли НЕ являются правами доступа. Перевод: закрыть действующее назначение датой, создать следующее без пересечения. Смена LC1 сохранена в историческом shift_code. Новые назначения используют shift_id. Шкала с уровнями создаётся атомарно; изменения — новая версия, числовой ноль не равен отсутствию оценки. Не предустанавливаем корпоративские шкалы/пороги. Архивирование блокирует действующие зависимые записи.
## Импорт
Локальный ExcelJS из pinned Stage43, MIT; все файлы offline, без внешнего CDN. Импорт одного выбранного листа в один выбранный справочник: выбрать XLSX, лист и строку заголовков, сопоставить колонки, предварительная проверка, подтвердить транзакцию. Шаблон XLSX генерируется локально для каждого типа. Ключи: табельный номер; код; подразделение+код для оборудования/операций; сотрудник+начало для назначения; сотрудник+роль+начало для роли; название категории; категория+название навыка; название+версия шкалы. Сравнение ключей NFKC/trim/casefold, без автоматического восстановления архива. Ссылки по кодам/названиям категорий, не ФИО. Родительские подразделения могут быть в произвольном порядке. Коды в Excel — текстовые, числовые коды отклоняются во избежание потери нулей. Формулы/ссылки/ошибки в данных отклоняются. Новые записи, точные совпадения, изменённые существующие и ошибки отображаются отдельно. Обновление только с явным флагом, неназначенные поля сохраняются. Пустая назначенная ячейка очищает необязательное поле. Все ошибки блокируют весь импорт; события предварительно применяются на клоне БД, затем одной транзакцией с контролем версий; очередь 2000 событий, файл до 20 МБ, до 1000 строк/100 колонок, проверка каталога ZIP до распаковки (не абсолютная защита от вредоносных файлов; использовать доверенные XLSX). Публикация и передача пакетов по прежнему протоколу.
## Миграция v2 -> v3
003_lc2.sql аддитивно расширяет схему. Старые snapshot v2, манифест, backup и пакет v2 проверяются на исходной версии и хэшах, затем мигрируют локальную копию; UUID, журнал, публикации и старые payload не переписываются. При наличии записей в ранее неиспользовавшейся legacy-таблице person_role миграция блокируется до явного сопоставления, исходная база сохраняется. При публикации v3 все сотрудники должны обновиться до LC2.0; старый LC1.3 не читает v3. Перед обновлением — передать/принять изменения, резервная копия, закрыть вкладки, установить новый каталог versions/lc2.0, index.html заменить последним. Не откатывать опубликованную v3 на LC1.3 без восстановления согласованной копии v2. История схемы и baselines не меняются. В старых событиях назначения новые поля отсутствуют; совместимость сохраняется без модификации хэшей. Новые ограничения могут выявить конфликт старого ожидающего события: очередь не удаляется, требуется разбор.
