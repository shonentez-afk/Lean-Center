# Физическая модель БД v1
Файл [schema_v1.sql](../db/schema_v1.sql) — кандидат DDL SQLite, не рабочая база предприятия. Схема нормализует общие данные; payload_json сохраняет полные данные legacy редактора, но критические связи и факты хранятся в типизированных колонках. Вложения отдельно в ZIP/каталоге по sha256; ссылки и метаданные в БД.
 
## ER-связи
- org_unit 1:N org_unit/equipment/operation/person_assignment; person 1:N person_assignment/person_role; profession 1:N role_requirement.
- operation 1:N document/skill/training_assignment/mentor_authorization; document 1:N document_revision 1:N document_step/document_approval; document_relation связывает версии СОП/TWI.
- frv_study 1:N frv_measurement. Сохранять исходный замер, контекст и версию.
- skill_category 1:N skill; rating_scale 1:N rating_level; role_requirement и coverage_requirement задают целевой уровень; assessment_session 1:N assessment_item. Последний подтверждённый наблюдаемый навык определяется датой; истечение срока, допуск и требования проверяются отдельно. Нельзя сравнивать разные шкалы без явной карты эквивалентности.
- training_assignment 1:N training_session; assessment_session связывает обучение с практической проверкой; mentor_authorization подтверждает право обучать.
- checklist 1:N checklist_version 1:N checklist_criterion; audit_session 1:N audit_response; составные FK исключают смешивание версий критериев. v_audit_scores не включает аннулированные, legacy fractional и ненаблюдавшиеся ответы в бинарный процент. Legacy отчёты воспроизводятся отдельным адаптером.
- finding -> action_item -> action_verification; development_plan -> development_goal -> action_item. schedule_event единый календарь.
- publication / exchange_package / change_event / exchange_conflict / legacy_mapping — обмен, аудит изменений и идемпотентная миграция.
 
## Инварианты сервисов (DDL недостаточно)
UUID, даты ISO, JSON-валидация по схемам, циклы и пересечения интервалов, соответствие операции/версий документов/обучаемого, обязательные ответы при финализации, запрет обхода immutable через смену статуса или перенос дочерней записи, защита шкал и исторических версий, проверка источников polymorphic attachment_link и schedule_event, единый реестр ревизий для событий, авторизация издателя сетевыми ACL. Все переходы выполняются через транзакции сервисов; DDL v1 требует усиления до production. Удаление истории запрещено, исправления через supersedes/void. Доказательства эффективности CAPA — проверка сопоставимого контекста, версия критериев, повтор критического нарушения, достаточность наблюдений. Не превращать средний балл в разрешение на работу.
 
## KPI
Покрытие компетенций = число сотрудников с действующей подтверждённой квалификацией нужного уровня / требуемое число; показывать оба числа и дефицит, без суммирования разных смен. Обеспеченность СОП = операции с действующим обязательным СОП / операции, которым он требуется (политика требований ещё проектируется). Выполнение обучения = завершённые назначения / подлежащие завершению за период; подтверждённая компетенция отдельно. L1 = yes/(yes+no), полнота наблюдения отдельно, критические нарушения отдельно, версии отдельно; 0 знаменатель -> NULL. Просрочка = открытое мероприятие с due_on раньше локальной даты. ФРВ — только сопоставимый контекст и секунды.
