### Реализация

- План с основанием, ответственным, подразделением, валютой, контрольной датой; метод времени или прямой денежной оценки. План после первой проверки зафиксирован, последующие проверки и переносы в журнале событий. Валюта выбирается из RUB/EUR/USD/KZT/CNY/BYN/GBP (по умолчанию RUB); без конвертации.
- Единый калькулятор: часы = (секунды до − после) × годовой объём / 3600; валовый расчёт = часы × ставка × доля реализации или прямой годовой ввод. Чистый годовой = валовый − ежегодные затраты; первый год = чистый − инвестиции; ROI первого года = первый год / инвестиции × 100%; простая окупаемость в месяцах = 12 × инвестиции / чистый годовой при положительных инвестициях и чистом эффекте. При нулевых инвестициях ROI и окупаемость не определены. Отрицательный эффект не обнуляется. Это не NPV/IRR и не бухгалтерские проводки.
- Для проверки ФРВ требуется завершённое исследование, одобренное сравнение полных циклов, точный исходный файл с SHA-256 и действующие проверки связанных мероприятий. Модель вычисляет разницу из исходника; для иных мероприятий нужен вручную документированный расчёт. Проверяющий отличается от владельца. Повторный учёт одного файла ФРВ в активных карточках запрещён. Связанные с одним ФРВ мероприятия не получают отдельные суммы автоматически.
- Денежный факт хранит период, валовую экономию, текущие затраты, инвестиции, регистратора, ссылку на событие проверенного расчёта и текст первичного основания. Суммы хранятся в сотых долях валюты. Черновик → независимое подтверждение → при необходимости аннулирование с основанием. Факты не создаются из годового сценария автоматически. Подтверждение внутри центра не означает наличие полномочий финансовой службы; корпоративский регламент и первичные документы проверяет предприятие.
- Дашборд, общая аналитика и дерево метрик используют единый реестр. Денежный итог только по подтверждённым фактам, целиком входящим в период, с актуальными доказательствами, раздельно по валютам. Не складывать план и проверенный сценарий с денежными фактами, не распределять факты автоматически по месяцам, не суммировать годовой потенциал разных проектов без проверки пересечений. Если доказательство утратило силу, прошлый факт сохранён, но исключён из актуального денежного итога. Повторная проверка модели не переписывает ссылку старого факта.
- Срок контроля из карточки отображается в существующем календаре, «Мой план» и карточке сотрудника; без копирования в schedule_event. Переходы из ФРВ, мероприятий, дашборда, метрик и аналитики открывают тот же реестр. Экспорт XLSX сценария, фактов и агрегатов.
- Новые автоматические проверки: формулы, миграция v13, ссылки и контроль доказательств, отсутствие двойного учёта, пересечение периодов, валюта, аннулирование, пакет старой схемы, публикация/восстановление, сквозной браузерный сценарий. Требуется полный CI Windows/Linux актуального HEAD, затем пользовательская приёмка. Реальные SMB/ACL, финансовые правила, нагрузка и устройства остаются открытыми. Не выдавать ZIP до PASS.

## KPI
Покрытие компетенций = число сотрудников с действующей подтверждённой квалификацией нужного уровня / требуемое число; показывать оба числа и дефицит, без суммирования разных смен. Обеспеченность СОП = операции с действующим обязательным СОП / операции, которым он требуется (политика требований ещё проектируется). Выполнение обучения = завершённые назначения / подлежащие завершению за период; подтверждённая компетенция отдельно. L1 = yes/(yes+no), полнота наблюдения отдельно, критические нарушения отдельно, версии отдельно; 0 знаменатель -> NULL. Просрочка = открытое мероприятие с due_on раньше локальной даты. ФРВ — только сопоставимый контекст и секунды.
