# Lean Center — размещение на сетевом диске (LC1.2)

## Первый запуск
1. Распаковать ZIP полностью в сетевую папку. Не запускать index.html из окна архива.
2. Пример постоянного пути: \\SERVER\Share\LeanCenter\index.html.
3. Создать ярлык на этот файл и раздать сотрудникам. У всех должен быть один постоянный путь (не чередовать букву диска и UNC). Открывать в корпоративном Chrome/Edge.
4. Сервер приложений, Node.js, Python, SQLite, Docker и Connector на ПК сотрудников не нужны. Все библиотеки поставляются локально. WASM передаётся как данные в отдельном JS-файле: загрузка через fetch при file:// не используется.
5. В разделе «База и обмен» выбрать сетевую папку данных. Для эксплуатации рекомендуется отдельная папка рядом с программой, например \\SERVER\Share\LeanCenter_Data. Для учебного испытания — отдельная тестовая папка. Каждый браузер должен один раз предоставить разрешение на доступ; ярлык сам по себе не предоставляет права записи.
6. «Проверить доступ». Единственный уполномоченный издатель принимает изменения и публикует базу. Остальные сотрудники открывают опубликованную базу, редактируют локально, отправляют пакеты и обновляют снимок. Если выбор папки запрещён политиками, использовать ручной обмен.
7. Не добавлять учебные данные в рабочую базу. Демонстрационные данные только в тестовой копии.

## Состав поставки
index.html — неизменный адрес ярлыка;
versions/lc1.2/app/ — код приложения и конфигурация схемы;
versions/lc1.2/vendor/ — SQLite WASM и ECharts;
versions/lc1.2/assets/ — стили;
versions/lc1.2/licenses/ — лицензии библиотек;
app-manifest.json — размеры и SHA-256 программных файлов;
README_DEPLOY_RU.txt — настоящая инструкция.
В ZIP нет пользовательской базы, документов, пакетов изменений и резервных копий.

## Данные
В выбранной папке данных создаются Database/, Exchange/, Backups/ при первом соответствующем действии. Documents/ и Reports/ будут задействованы на следующих этапах. Не выдавать сотрудникам право менять index.html, versions/ и другие программные файлы. Настроить файловые ACL через администратора; публикация Database/ — только издателем. Текущий LC1 требует readwrite-разрешения на корневую папку данных; права доступа к вложенным папкам проверяются при операции. Сетевой обмен не является серверной авторизацией.

## Обновление без изменения ярлыка
Перед обновлением сотрудники отправляют ожидающие изменения и скачивают проверенную резервную копию. Издатель публикует согласованное состояние. Закрыть вкладки на время обновления.
Каждая новая поставка получает новый каталог versions/<номер>. Сначала скопировать новый каталог версии целиком и сверить SHA-256 по app-manifest.json; только затем заменить корневой index.html и сопроводительные файлы. Не переименовывать сетевой путь входа. Не удалять старую версию до успешного запуска новой. Для отката использовать предыдущий index.html, если схема базы совместима; при несовместимой миграции восстанавливать согласованную резервную копию.
Не использовать синхронизацию папок с удалением отсутствующих файлов. Не распаковывать поверх данных, не удалять Database/, Exchange/, Backups/, Documents/, Reports/. Локальный IndexedDB привязан к браузеру и файловому контексту: стабильный путь снижает риск потери доступа к кэшу, но не заменяет резервную копию. При переходе со старого цельного HTML сначала скачать .leanbackup, затем восстановить его в новом index.html и повторно выбрать папку.

## Приёмка
Проверить ярлык и запуск с двух корпоративных ПК, доступ к отдельной папке, публикацию и импорт изменений, конфликт версий, потерю сети, повторный запуск, резервное копирование и обновление версии. Локальные file:// тесты CI не равнозначны реальному SMB/UNC и корпоративским политикам. Не считать сетевой режим принятым до испытания.
