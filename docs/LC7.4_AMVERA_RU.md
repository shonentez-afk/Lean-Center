## Реализация LC7.4.0

- Использует существующий SQL.js, схему v17, миграции, mergePackage, проверку ревизий, исходников и prepareSnapshot. Автономный UI и сетевой режим LC7.3B не изменены. PostgreSQL не нужен.
- Последовательная очередь одного серверного процесса. Каждый успешный пакет публикует новый снимок автоматически. Повтор идентичного ID пакета не создаёт дубликат. Конфликт отклоняет всю транзакцию; данные остаются у клиента. Старые публикации в журнале сохраняются.
- /data/lean-center-pilot/state.sqlite заменяется только подготовленным снимком через временный файл, fsync, rename, fsync каталога. Ответ об успехе — только после проверки прочитанных байтов. При неоднозначном сбое запись блокируется до проверки и рестарта. Нет WAL, нет общей записи в SQLite с нескольких процессов. В Amvera нужна ровно одна реплика. writer.lock создаётся эксклюзивно и снимается при штатном закрытии; после аварийного завершения необходимо удостовериться, что старый процесс остановлен, проверить данные/бэкап и вручную снять старый lock. Не удалять блокировку действующего сервера. На реальной Amvera семантика fsync/rename и жизненный цикл контейнера ещё не проверены.
- Отдельные JSON исходников СОП/ФРВ по SHA-256; проверка содержимого до принятия и при старте. Источники доступны только после регистрации в снимке. Незарегистрированный загруженный файл может остаться сиротой. Удаление пока не автоматизировано.
- Лимиты первого стенда: 16 МиБ снимок, 5 МиБ пакет, 30 МиБ источник, 256 МиБ исходники, 8 операций очереди. Это сознательные ограничения для 500 МБ RAM, не подтверждённая нагрузочная ёмкость. Полные снимки экспортируются после каждого пакета; будущая оптимизация по фактическим измерениям.
- Тестовые токены и роли editor/viewer задаются только секретной переменной LC_PILOT_USERS, без открытых паролей в Git. Токен должен быть 64 случайных hex-символа. Все авторизованные тестовые пользователи читают весь тестовый снимок; editor может отправить любой доменно допустимый пакет. Нет тонкой авторизации по предприятию/подразделению, привязки actor_id к серверной личности и производственного аудита доступа. Поэтому не использовать с рабочей базой. 
- Необязательная переменная LC_PILOT_DATA_DIR для локального теста (абсолютный путь); по умолчанию /data/lean-center-pilot. LC_PILOT_DEMO=1 обязательна. Не записывать секреты в код и не передавать их в чат. При отсутствии секретов сервер не запускается.

## API (пока без интеграции в основной UI)

GET /healthz — публичная проверка готовности, без данных. Остальные API требуют Authorization: Bearer TOKEN.
GET /api/v1/session — тестовая учётная запись/роль.
GET /api/v1/snapshot — манифест и SQLite base64.
PUT /api/v1/documents/<sha256>?kind=sop или frv — точный UTF-8 JSON исходника.
GET /api/v1/documents/<sha256> — точный исходник, если зарегистрирован.
POST /api/v1/packages — пакет lean-change-v1 от текущей схемы и существующей публикации; ответ подтверждает публикацию или возвращает ошибку. Повторять тот же пакет после потери ответа.
Нет маршрута загрузки чужих произвольных баз, админ-импорта, очистки или резервного восстановления из Интернета.
