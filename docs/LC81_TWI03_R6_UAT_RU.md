# R6 — контрольный маршрут пользовательской приёмки

Проверяем только интегрированную ветку feature/lc81-twi03-r6-final-qa. Перед тестом зафиксировать SHA кандидата, номер успешного Actions, дату предприятия, учётную запись и область доступа. Для испытаний применять отдельную учебную базу; не создавать искусственные факты в действующей базе. Не считать открытие раздела доказательством выполнения всех его операций.

Сравнить по [сверке оригиналов](LC81_TWI03_R6_SOURCE_AUDIT_RU.md): состав полей, названия, версии, связи, даты, формулы, пустые подписи, читаемость при печати и переносы строк. Отдельно проверить 4/12 по изображению оригинала, 5 по трём блокам шагов, 6/8 по одинаковому составу, 7 по целям и факту, 9/13/14 по числу критериев, 15/16 по действующим суммам и основаниям, 17 по срокам трёх программ. Отметить визуальные отличия, не требовать копирования демонстрационных данных. Допускается цифровое представление, если владелец подтверждает его пригодность.

## Безопасность поставки CloudCore

1. Выбрать артефакт последнего успешно проверенного коммита, сверить sourceCommit, digest и версию runtime; не использовать промежуточный b00e1c89 как финальный.
2. Перед любым живым действием получить отдельное разрешение владельца на время работ. Сверить текущую read-only диагностику, active SHA, HTTPS, состояние блокировок и доступность резервных копий.
3. При INSTALL_BUSY не удалять lock и не завершать реальные процессы вручную. Причина и штатный порядок восстановления описаны в DEPLOY_CLOUDCORE_RU.md и START_NEW_CHAT_RU.md. Согласованный контролируемый перезапуск, подтверждение возврата HTTPS и повторная диагностика являются предварительными условиями.
4. После освобождения блокировки только штатный контроллер: остановка, новая проверенная копия, проверка кандидата на отдельном восстановлении, побайтовая неизменность копии, переключение версии и проверка health/границы доступа. При отказе — предусмотренный возврат исполняемой версии; не перезаписывать рабочую БД произвольным восстановлением.
5. Принять обновление только после проверки фактического SHA, доступности данных и входа разрешённых ролей. Зафиксировать итог в документации. Реальная база/контроллер пока не затронуты.

## Правила, требующие решения владельца

Норма три аудита за календарный год установлена стандартом; единица зачёта повторных/совпадающих наблюдений и дополнительное право обучать по конкретной операции — локальные правила. Действующие проверки не ослаблять и не выдавать локальный выбор за дословное требование стандарта. Утверждение СОП, LC8.2/8.3 и реальный внешний ИИ — не скрытые критерии PASS R6.
