## Архитектурные решения

- Один backend Node.js, SQLite и существующий защищённый механизм единственной очереди записи. **Python и Redis для этого этапа не нужны** (прямое требование файла 03_Внедрение_на_базе_LC8.3.4.md). Не менять одновременно язык, базу и развёртывание. Не подключать отдельный сервис без измеренной необходимости.
- «Мой план» — проекция открытых обязанностей; уведомление — адресное событие. Прочтение никогда не исполняет поручение. Согласование, ввод, ознакомление, обучение, практическая оценка и допуск остаются отдельными фактами.
- Переиспользовать lc83_sop_round, lc83_sop_decision, lc83_sop_notice, оценку влияния, реестр ознакомлений и обычные назначения TWI. Не создавать второй маршрут, реестр задач или источник истины о действующей редакции. История и старый СОП неизменны до фактического ввода.
- Два входа ведут к одному точному раунду и редакции. При каждом чтении и действии заново проверять аккаунт, область, актуальное назначение, этап и полномочия; не переносить права из старой ссылки, события или совмещённой роли. Технический администратор не утверждает СОП без бизнес-полномочий.
- Внешняя доставка отдельна от ленты и записи доменного факта. Ошибка доставки не меняет доменный статус. Системный баннер не доказательство прочтения/получения/ознакомления; Web Push — не аварийное оповещение.
- Не менять утверждённые 20 вопросов L1, конструктор СОП, его текущий ИИ, TWI, допуски и схемы исторических данных без отдельного согласования. main, Amvera, действующая БД, рабочий VPS и деплой не затрагиваются.

## Политика адресатов

Активный согласующий получает действие при активации своего этапа. При последовательном маршруте будущий этап молчит; при параллельном каждый получает своё. Возврат — поручение автору/ответственному за доработку; участники могут видеть разрешённую историю, не получают автоматически push. Утверждение и ввод — соответствующий назначенный сотрудник. Запланированный серверный ввод не создаёт второе ручное поручение. Заблокированный/отменённый ввод не считается фактической публикацией. Ознакомление — только назначенному исполнителю; завершение — ответственному в пределах доступа. Напоминание TWI — обучаемому; прочие обязанности добавлять только по фактическим назначениям. Руководителю — разрешённые сводки, а не все персональные уведомления участка. Не рассылать старую историю при импорте.

## Контракт A

- Дополнительная проекция собственного СОП-плана из текущего раунда и доступных этапов. При отсутствии обычного plan.read допускается только личный СОП-план для актуального согласующего/автора/получателя ознакомления, без календаря и планов других людей. Состояние очереди не зависит от ленты.
- Резюме хранится в существующем submit_note и обязательно для новых раундов. Исторический раунд не переписывается. Сопоставление сравнения уникального содержания/действия, осторожная позиционная пара и несопоставленные фрагменты; отметка ручной проверки, правильная позиция исходного/нового фото. sameWorkContent остаётся отдельной строгой проверкой.
- API GET /api/lc81/notifications?filter=all|unread|actions&cursor=ID&limit=1..50, POST /notifications/read {id}, POST /notifications/read-all {snapshot}. Получатель только из checkedAccount; лента/счётчик/прочтение используют общую живую проекцию. События остаются в lc83_sop_notice; отдельная lc82_notice_read не меняет существующие позиционные INSERT. Снимок read-all — ID последнего видимого события, сервер сверяет его владельца и ограничивает по порядку вставки; вновь добавленные записи остаются непрочитанными. В ленте действия упорядочены по просрочке и сроку, история — по времени и ID. Страницы с утратившим актуальность курсором требуют обновления.
- Флаг LC82_INBOX_ENABLED=0 отключает ленту, по умолчанию включена в кандидате. Состояние прочтения проверяется при записи и восстановлении. Нет внешней доставки, подписок, напоминаний TWI или новой очереди до пакетов B/C. Кнопка в шапке, адаптивное окно, Escape и возврат фокуса, актуальный серверный счётчик при следующей проверке сеанса. Не хранить приватные уведомления на клиенте.
- В A оценивается текущий CI, не объявлять SUCCESS до получения фактических результатов. Для B/C предусмотрена отдельная приёмка.
