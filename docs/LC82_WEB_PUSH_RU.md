## Архитектура
- Единый Node.js/SQLite, без Python, Redis, отдельного почтового сервера и дополнительной runtime-зависимости. Реестр обязанностей и внутренняя лента независимы от транспорта.
- /sw.js на корне, с Service-Worker-Allowed: /, no-store, CSP worker-src self. Service worker не перехватывает fetch, не хранит исходники, персональные данные или API-ответы в CacheStorage. На системном экране фиксированный общий текст, неприватное имя портала, один tag lc82-action. В зашифрованном payload — версия и непрозрачный ID уведомления либо null для теста, без ФИО, названий операций, СОП, полномочий, оценок. Клик открывает новую вкладку /#lc82-notice=UUID, не перезаписывает открытую рабочую форму. Фрагмент извлекается в память страницы и удаляется из URL; после входа сервер проверяет получателя, доступ и точный связанный объект. Чтение — отдельно от согласования, ознакомления, обучения и допуска.
- Пользователь явно подключает личное устройство, даёт browser permission, выбирает типы push, разрешённые дни/время в часовом поясе предприятия. Подключать только личный телефон/ПК; на общем ПК не включать. До 5 активных устройств на аккаунт, 2000 в текущем хранилище. Список устройств содержит только метки и состояние; endpoint/auth/p256dh не раскрываются через API. Отзыв удалённого устройства, тест не чаще раза в минуту; при явном выходе локальная подписка отзывается и браузер пытается убрать показанные уведомления. При смене аккаунта проверяется принадлежность; автоматического переноса старой подписки нет. Пароль, блокировка или новая credential_revision делают старую подписку недействительной. Истечение обычной веб-сессии не равно явному отключению личного Push.
- Транспорт RFC 8291 aes128gcm + RFC 8292 VAPID ES256 на Node crypto; фиксированное тело, свежий ECDH и соль, проверка ключа P-256. Разрешены только поддерживаемые HTTPS endpoints FCM, Mozilla и Microsoft WNS; порт, учётные данные URL, произвольные домены и redirects запрещены; IPv4 DNS-результат проверяется на публичную маршрутизацию и закрепляется для TLS-запроса. IPv6-only и неподдержанные endpoint-форматы пока не поддерживаются. Apple/iOS не включён в текущий транспорт. Проверить реальные endpoint-форматы на целевых браузерах; политика сети предприятия может блокировать provider. Ссылки: https://www.rfc-editor.org/rfc/rfc8291 и https://www.rfc-editor.org/rfc/rfc8292.
- Очередь lc823_push_job отдельна от фактов и внутренних напоминаний; lc823_push_device хранит capability подписки в закрытом серверном хранилище; lc823_push_policy — отдельный администраторский рубильник. Данные подписок не зашифрованы отдельным ключом на диске: действуют существующие права приватного checkpoint и закрытые резервные копии. Нельзя публиковать checkpoint, endpoint, ключи или дамп. Перед постановкой и непосредственно перед отправкой — проверка живой ленты, непрочитанности, прав и состояния, текущих сроков, подписки, credential_revision, deployment binding и предпочтений. Отсечки регистрации по двум ordinal исключают историю до подключения, при повторном разрешении политики отсечки обновляются. Доставка текущих событий согласования, ознакомления, TWI-напоминаний и выбранных информационных фактов; категории аудитов/мероприятий пока зарезервированы, не означают, что их события уже подключены.
- Задания сохраняются до сети, одна группа до 32 на устройство, не более 4 групп за проход (до 128 новых записей). Worker стартует вместе с HTTP и работает раз в 15 с, без параллельных проходов. Штатная очередь записи не держится при сетевом I/O. Возраст события максимум 24 ч, тест 15 мин, provider TTL максимум 300 с и ограничен оставшимся окном доставки. Ночное окно относится к дню его начала. Не обещать точное время фактического показа средствами ОС. Состояния pending/retry/sending/accepted/cancelled/expired/failed/uncertain; HTTP 429/503 — ограниченный повтор с Retry-After (до четырёх попыток), 404/410 — истёкшая подписка, прочие отклонения — отказ. Если исход внешней передачи неизвестен или процесс прерван после claim, не повторять автоматически, помечать uncertain. Exactly-once у внешнего провайдера не гарантируется. accepted означает ответ сервиса, не факт доставки, показа, прочтения или выполнения. Отправленный до отзыва баннер нельзя гарантированно забрать с потерянного устройства; текст общий, TTL короткий, ссылка заново авторизуется.

## Разрешение только на выделенном размещении
Не менять текущий VPS или production во время разработки. По умолчанию LC82_PUSH_ENABLED отсутствует/0. При отдельном согласованном пилоте на **постоянном HTTPS** администратор размещения задаёт вне Git и архивов:
- LC82_PUSH_ENABLED=1
- LC82_PUSH_ORIGIN — точное совпадение LC81_ORIGIN (не localhost и не IP)
- LC82_PUSH_DATA_DIR — точный абсолютный путь LC81_DATA_DIR
- LC82_PUSH_INSTANCE — 64 строчных hex-символа, случайный уникальный секрет данного экземпляра
- LC82_VAPID_PRIVATE — стабильный P-256 private key (32 байта в base64url)
- LC82_VAPID_SUBJECT — mailto:адрес ответственного за техническую поддержку (действительный контакт, не выдуманный)
- LC82_INBOX_ENABLED и LC82_BACKGROUND_ENABLED не должны быть 0; LC81_SCHEDULER_DISABLED не должен быть 1.

Генерировать ключи только на согласованном сервере в закрытый файл вне release (пример команды без реальных секретов):
```sh
umask 077
node --input-type=module -e 'import {createECDH,randomBytes} from "node:crypto"; const k=createECDH("prime256v1"); k.generateKeys(); const d=k.getPrivateKey(); console.log("LC82_VAPID_PRIVATE="+Buffer.concat([Buffer.alloc(32-d.length),d]).toString("base64url")); console.log("LC82_PUSH_INSTANCE="+randomBytes(32).toString("hex"));' > /private/path/lc82-push.env
```
Путь — пример, заранее создать защищённую папку, не перезаписывать существующий ключ при обновлении. Остальные переменные задавать в защищённом окружении процесса. После включения транспорта в окружении и корректной настройки календаря — администратор входит в «Фоновые уведомления», явно разрешает Web Push. Затем пользователь в колокольчике сохраняет типы/окно доставки, открывает «Устройства Web Push», называет личное устройство, включает Push и запускает проверку. Отказ от браузерного разрешения не влияет на Мой план и ленту. Выключение администратором отменяет ещё не отправленные задания; перезапуск с LC82_PUSH_ENABLED=0 отключает сеть. Не использовать реальные ключи и instance в CI, резервных копиях для тестирования, новом домене или пробном сервере. LC81_SCHEDULER_DISABLED=1 отключает все планировщики. Переезд origin/пути/instance или ротация VAPID требуют отдельного подключения; восстановленная копия с новой конфигурацией не имеет действующей политики/подписок. Если оператор намеренно копирует **всю** боевую конфигурацию и ключи вместе с данными, изоляция не гарантируется — запрещено. Рабочий запуск и установка не модифицировались в этом пакете; необходима отдельная проверка способа передачи env реальной службе VPS.
