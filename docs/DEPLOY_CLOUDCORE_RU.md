# CloudCore VPS — отдельная проверка SSH

Ветка `feature/cloudcore-vps-qa` изолирована от main, Amvera и LC8.1-PARITY. База кода `d5eabd38fdace9510c6ef0c2fb6ab3ed046a0adf` ещё не означает приёмку LC8.1. SSH-диагностика сама по себе приложение не разворачивает.

Workflow `.github/workflows/cloudcore-ssh-qa.yml` запускается только при изменении этого файла в указанной ветке. Он не выполняет checkout, не использует сторонние Actions, не выдаёт права GitHub token, не читает и не изменяет данные Lean Center, не устанавливает пакеты, не вызывает sudo. На VPS проверяются только непривилегированная учётная запись lean-deploy и наличие Git. SSH проверяет заранее подтверждённый ключ хоста ED25519; сканирование и автоматическое доверие неизвестному хосту запрещены.

Секреты CLOUDCORE_SSH_KEY и CLOUDCORE_KNOWN_HOSTS уже создаёт владелец. CLOUDCORE_HOST нужен только если адрес скрыт хешированием known_hosts или неоднозначен. Адрес VPS, ключи и подробный SSH вывод не публикуются в репозитории и в логах. В CI выводится только обезличенный результат.

Для рабочей эксплуатации перенести SSH ключ в отдельное GitHub Environment с ограничением веток и доступом доверенных сопровождающих; заменить ключ на отдельный служебный с ограниченным набором разрешённых действий. GitHub Secrets уровня репозитория доступны другим доверенным workflow этого репозитория. SSH restrict сам по себе не запрещает выполнение произвольных команд от имени lean-deploy. Не выдавать sudo, root или доступ к Docker socket без отдельной модели полномочий.

Публичный HTTPS, резервирование и восстановление проверяются отдельно перед использованием стенда за пределами локальной диагностики.

## Тестовая установка LC8.1 на CloudCore

Workflow `.github/workflows/cloudcore-install-qa.yml` собирает точный коммит ветки с Node.js 22 по закреплённым исходникам и lock-файлу. Он запускается по push изменений исходников, проверок или рецепта CloudCore в `feature/cloudcore-vps-qa`. GitHub runner собирает архив, вычисляет SHA-256 и передаёт его через SSH со строгой проверкой ED25519. Для сборки требуется GitHub token только на чтение репозитория. На CloudCore не нужны npm, Docker или системная установка Node.js.

- Установка выполняется от `lean-deploy` на Linux x86-64. Каталог `~/lean-center-cloudcore-qa/<SHA>` содержит собственный Node.js, приложение и новое хранилище `data/`. После проверки каталог публикуется атомарно. Повтор того же SHA подтверждает ранее установленный экземпляр. Существующие данные не перезаписываются.
- При первом запуске используется зона `Asia/Krasnoyarsk`. Пароль пользователя `admin` создаётся на VPS и сохраняется в файле `admin-password` с правами 0600. Файл доступен локально владельцу `lean-deploy`. Храните пароль вне GitHub, журналов и переписки.
- Проверка подтверждает `/healthz`, страницу входа, отказ без сессии и с неверным Origin, вход администратора, свойства cookie и сохранение записи «Учебный участок CloudCore» после перезапуска без начального секрета. После проверки приложение штатно остановлено. Для локального повторного запуска от `lean-deploy` используйте `bash ~/lean-center-cloudcore-qa/<SHA>/deploy/cloudcore/start.sh`.
- Приложение слушает только `127.0.0.1`. При ручном запуске порт `18081`, ожидаемый origin `https://localhost:18081`. HTTP-проверка на VPS не проверяет браузерный HTTPS. Для доступа через браузер потребуется отдельно настроенный закрытый HTTPS-доступ. Внешний ИИ выключен. Workflow не импортирует данные и не меняет системные службы, SSH, firewall или Amvera.

## Обновление действующего тестового стенда

Push в `feature/cloudcore-vps-qa` с изменениями сайта или сборки запускает автоматическое обновление. Сборка создаёт локальную карту контрольных сумм из точного коммита. Её не нужно обновлять вручную для CloudCore. Ветка и коммит проверяются до передачи архива.

На VPS новая версия сначала устанавливается в отдельный каталог и проходит проверку с новой учебной базой. Затем действующий тестовый стенд штатно останавливается. Создаётся проверенная резервная копия его базы, а новая версия запускается на отдельном восстановлении этой копии. Только после успешной проверки и подтверждения, что пробный старт не изменил её, переключается версия исполняемых файлов. Действующий каталог данных и именованный туннель сохраняются. Если новая версия не запускается, контроллер возвращает предыдущую версию. Изменения, требующие преобразования существующей базы при старте, требуют отдельной процедуры миграции.

Резервные копии до обновлений и штатные ежедневные копии хранятся под `~/lean-center-cloudcore-qa/qa-backups/`. Автозапуск и расписание используют актуальную версию через тот же контроллер. Успешный результат в Actions — `CLOUDCORE_QA_PROMOTED` или `CLOUDCORE_QA_ALREADY_ACTIVE`.
