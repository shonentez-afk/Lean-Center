## 2. Аудит существующего интерфейса

Плюсы — все сигналы рассчитаны из существующих фактов; большинство карточек ведут в профильный раздел. Недостатки — много равнозначных элементов и нулей, отсутствует единый явно показанный срез, период месяца смешивается с текущим состоянием, справочные количества занимают место управленческой сводки. Нет компактной сводки покрытия компетенций. В отдельных метриках переход ведёт в широкий реестр, а не в точную выборку.
src/modules/training/screens.js::analyticsPage: девять тематических вкладок. Уже есть динамика L1 по месяцам, проблемные критерии, повторения, тепловая матрица, действия; аналогичная детализация оценок, сравнение самооценки с аудитом, СОП, ФРВ, экономика, подготовка. twi-effectiveness-view.js: результативность, время, сравнение по наставникам/участкам, повторное обучение, компетенции, экономические связи. center-overview.js::centerMetrics — дерево 30 показателей с определениями, но часть маршрутов не передаёт точную выборку. LC7.2: помощник в L1 и дереве метрик получает текущий фильтр, в остальных аналитических вкладках явно даёт общую сводку. Расширить адаптеры контекста всех отчётов.

## 3. Целевой дашборд: ежедневная работа
Шапка: предприятие/подразделение (при доступности точной фильтрации), период результата, дата среза и сведения о рабочей копии/публикации. Не выдавать локальную копию за онлайн-состояние всей организации. По умолчанию текущий месяц для фактов, текущая дата для рисков. Отдельный переключатель периода результата; не менять исторический период риска без явной семантики.
Первая зона — 6 основных карточек:
- Компетенции: требования без разрыва / все действующие требования, отдельно дефицит обеспеченности по заданным нормам; не равно допуску.
- Подготовка: завершено из начатых в выбранной когорте, отдельно просрочки и повторная комиссия.
- TWI: назначено/завершено, при необходимости доля первой положительной практики с основанием; первый допуск не текущий допуск.
- Аудиты L1: количество фактов и наблюдений, методики раздельно; годовая норма — отдельная контрольная карточка.
- Мероприятия: открытые, просроченные, ожидают проверки результативности.
- Экономика: подтверждённый чистый факт по валютам за закрытые периоды; план и факт не суммировать, нулевой результат не равен отсутствию фактов.
Вторая зона — «Требует внимания»: только ненулевые сигналы по срочности, сроки, источник; 5–8 строк и «Показать все». Не складывать пересекающиеся сигналы. При пустой базе показывать отсутствие исходных данных, а не зелёный успех. Сохранять все существующие правила centerAttention. Не вводить произвольную оценку сотрудника.
Третья зона — компактные тенденции: обучение/практика, аудит (одна методика/серии раздельно), мероприятия и подтверждённый эффект; 2–3 небольших графика, точный drill-down. Ближайшие дела из существующего календаря (7 дней, настраиваемый горизонт; без записи новых планов). Кнопка помощника — объяснить именно текущий срез. Не включать чат, который занимает половину главного экрана.
Справочные количества и большой график справочников — в управление/состояние данных; быстрые ссылки на модули — в навигацию. Сохранить кнопки импорта в соответствующем разделе. При необходимости оставить сворачиваемые служебные ссылки на главной. Представления «центр / участок / мой план» строить на существующих связях, не выдавать локальный фильтр за контроль доступа.

## 4. Целевая аналитика
Оставить все 9 видов и дерево метрик, но сгруппировать вкладки и использовать один шаблон: фильтры → KPI/определения → тренд/сравнение → причины и детализация → исходная запись/экспорт. Общие: период, подразделение, при необходимости смена, сотрудник/роль, методика/редакция; фильтры включать только там, где проекция достоверно их поддерживает. Сохранять фильтры при Back и переходе в карточку.
| Направление | Основная визуализация и анализ |
|---|---|
| Аудит L1 | Динамика числа наблюдений и доли «да» с знаменателем, Pareto отрицательных критериев, тепловая карта критерий × участок/инструктор, повторные контексты, связанные мероприятия; RC1/прил.13 не объединять |
| Практика | Доля первого положительного результата, распределение заключений, трудные критерии и повторная практика; не смешивать оценку и допуск |
| Самооценка / сопоставление | Профиль критериев отдельно от практики, совместимые версии и непокрытые наблюдения, переход к сравнению |
| Компетенции | Покрытие требований, дефицит по профессиям/навыкам/участкам, обеспеченность смен по заданным требованиям, неизвестные и истекшие отдельно; использовать существующий конструктор матрицы |
| Подготовка | Когорта начатых комплектов, состояние трёх документов, этапы и фактические смены, просрочки и основания повторной проверки, детализация без повторного учёта общего задания |
| TWI | Динамика когорты, число назначений, первый/текущий допуск раздельно, первая и повторная практика, медиана времени до допуска и объём подтверждённых минут; сравнение сопоставимых выборок |
| СОП | Актуальность редакций/пересмотр, оценка по отдельным методикам, наличие TWI/ФРВ и источников, переход к версии |
| ФРВ | Структура времени ВДЦ/М1/М2 по фактам, Pareto потерь с указанной базой, до/после только сопоставимых измерений; отсутствие причины не превращать в придуманную |
| Экономика | План/факт по явно покрытым закрытым целям, динамика подтверждённого факта по валютам, водопад причин отклонений только по зарегистрированным разборам, проверка источников |
| Мероприятия (сводный блок/подраздел аналитики) | Поток по статусам, возраст открытой работы, просрочено, выполнено, ожидает проверки, подтверждена эффективность; использовать actionRows/actionStatus, не вводить новый реестр |

Компетенции и мероприятия можно вывести как новые тематические аналитические представления на существующих проекциях, без новых бизнес-сущностей; действующие девять вкладок не удалять. Не требовать отдельного BI/сервера. ECharts уже включён локально; графики должны быть доступными через эквивалентную таблицу, оси/единицы/период и точные переходы. Тематические графики без декоративной круговой диаграммы там, где сравнение лучше показывает столбец. Приоритеты — на основе фактов; цвет дополняет статус/текст, не заменяет его.

## 5. Контракты и приёмка
1. Единая read-only проекция для карточек, таблиц, графиков, экспортов и помощника; существующие расчёты не копировать.
2. Для каждой метрики: ID, значение, числитель/знаменатель при наличии, единица, период/срез, версия методики, фильтр/роль, определение, источник, сравнимость и доступность. «Нет данных» отдельно от 0. Предыдущий период сравнивать только с эквивалентной выборкой и длительностью; при невозможности — без дельты.
3. Drill-down должен дать именно записи, из которых вычислен показатель; если широкий реестр — обозначить это и добавить точный адаптер. Не менять бизнес-правила ради графика. Сопоставление прошлых периодов требует доказанного исторического среза; текущие состояния когорты явно подписывать.
4. ИИ читает те же факты локально, облаку по умолчанию общие темы; отдельно согласованный ограниченный агрегат и предпросмотр. В отчёте не придумывать цифры/причины/решения/допуски. Не выгружать данные автоматически.
5. Тесты пустой базы, синтетической смешанной выборки, двух методик, закрытых/открытых периодов ROI и нескольких валют, повторов, неизвестных уровней, смен, смены фильтров, drill-down/Back, сохранности ввода, 390 px, тем, offline, выгрузки. Проверить отображение 5000 сотрудников без массового создания DOM. Не менять структуру БД, принятую LC6.7.6 или основной branch.

### Аналитика центра: исследование конкретной темы
Общая шапка со срезом, подразделением, периодом; дополнительные фильтры только по допустимым измерениям (роль/сотрудник, смена, операция, профессия, версия методики, состояние, валюта). Различать текущий риск, факт события за период, когорту с текущим состоянием и доказанный исторический срез. На вкладках сохраняются методика, фильтры, сортировка, выбранная детализация и Back.
Представления: «Обзор центра» — сравнение тематических показателей; «Обучение и компетенции» — подготовка, TWI, практические оценки, компетенции/обеспеченность; «Наставничество и аудит» — L1, самооценка, сопоставление; «Стандарты и потери» — СОП, ФРВ; «Улучшения и эффект» — мероприятия и экономическая эффективность. Существующие девять аналитических вкладок сохранить, добавить аналитические представления компетенций и мероприятий на действующих проекциях. ROI-модель остаётся рабочим реестром, не вторым отчётом.
Единый шаблон каждой темы: 1) фильтры и границы данных, 2) основные KPI с числителем/знаменателем, 3) динамика или распределение, 4) проблемные группы/критерии, 5) точные первичные записи и связанные действия, 6) локальный экспорт текущей выборки и помощник. Не перегружать одинаковыми KPI и не заменять детальные таблицы графиками.
Сравнение периодов — только при сопоставимости длительности, методики, типа факта и фильтра; не пересчитывать прошлый риск из сегодняшних состояний. Если невозможно — явно «сравнение недоступно». Различать ноль фактов и отсутствие достаточного знаменателя. При сравнении людей/участков показать размер выборки, не вводить автоматические рейтинги. Вклад в отклонение не равен доказанной первопричине.

### Дерево метрик: три режима, не отдельный учёт
1. **Каталог**: поиск, сворачиваемые тематические группы, название, значение, тип среза, статус наличия данных, цель только при зарегистрированном нормативе, переход «Как рассчитано». Сохранить все 30 существующих показателей и XLSX.
2. **Декомпозиция**: выбранный показатель в корне → доступное измерение (например, подразделение → профессия → операция → сотрудник для покрытия требований) → точные строки/первичная запись. Для L1 — методика, подразделение, инструктор, критерий и аудит; для эффекта — валюта, период, подразделение, карточка/факт; для действий — статус, ответственный, источник. Не подставлять общие измерения, которые фактически не связаны с метрикой. Смену измерений разрешать только при поддержке определения, пустую группу показывать отдельно. На узких экранах — вертикальный раскрываемый список.
3. **Паспорт и связи**: определение, формула, единица, числитель/знаменатель, дата среза и период, правила включения/исключения, версия методики, источник, идентичность/уникальность, тип агрегации, допустимые разрезы, переходы в расчёт и первичные записи. Выделить утверждённые цели и их источник; без нормы не выдавать красный/зелёный статус. Связи отличать визуально и семантически: вычислительная зависимость, декомпозиция по разрезам, тематическая/диагностическая связь. Не суммировать проценты, уникальных людей в пересекающихся группах, разные валюты, разнородные показатели и пересекающиеся сигналы. Не создавать фиктивный общий индекс эффективности центра. Диагностические связи (например, дефицит навыка, практика, L1 и ROI) не объявлять формульной или причинной зависимостью.

Пример только для проектирования: покрытие требований 120/150 = 80%; непересекающиеся группы A 52/60, B 40/50, C 28/40. На уровне предприятия складываются числители и знаменатели, а не средние проценты. Нажатие группы C показывает 12 непокрытых требований и 28 покрытых, причины разрыва по действующим данным, первичные оценки, редакции и требования; далее к матрице/карточке сотрудника. Пример не рабочие данные и не корпоративский целевой уровень.

### Контракт единого реестра метрик
Статический ID и версия определения, группа, название, описание, единица, тип значения/агрегации, date basis (event/cohort/current/as-of), допустимые разрезы/роли, правила проверки применимости, ссылка на зарегистрированную цель при наличии, единый вычислитель из существующих проекций, evidence selector для точной выборки. Результат содержит value/numerator/denominator, availability, effective scope, method/version, evidence reference, comparison eligibility. Не принимать SQL, формулы, ID сотрудника или произвольные вычисления от ИИ. Нельзя подменять точную выборку широкой ссылкой без предупреждения. Для больших наборов — пагинация и ленивое раскрытие, не создавать весь DOM на 5000 сотрудников. Не хранить повторно бизнес-факты в таблице метрик; вычислять из принятой v17.
Дашборд потребляет небольшой набор тех же metric IDs, аналитика исследует их и специализированные существующие проекции, дерево раскрывает определения и доказательства. ИИ получает идентичный локальный срез; по умолчанию облачный запрос только по темам, расширение до разрешённых агрегатов только с отдельным предпросмотром и согласием. Рекомендации о направлении анализа, не утверждение причины/оценка личности.

### Регресс LC7.3A
Проверить все 30 метрик на смешанной синтетической базе и на пустой. Для каждой — равенство карточки, отчёта, дерева и XLSX при одинаковом срезе; точность числителя/знаменателя и списка строк, фильтры и возврат. Проверить различие события, когорты, текущего состояния и истории, уникальность людей, отсутствие знаменателя, раздельные методики и валюты, отмены/архив/устаревание, доступность измерений, отсутствие неутверждённых целей, мобильный интерфейс, локальный offline и неразглашение данных. Не объединять метрики с несовместимыми определениями. Продуктовый код в данном исследовании не изменён.
