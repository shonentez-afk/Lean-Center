# Центр TWI — первый испытательный запуск в Amvera (LC7.4.2)

**Только демонстрационные данные.** Не использовать реальные ФИО, оценки, СОП или рабочую базу без согласования с предприятием. Это испытательный контур, не промышленный релиз. Принятая автономная LC7.3B не заменяется.

> Обновление LC7.4.3: интерфейс Amvera отвергает кавычки в секретах. Использовать HEX1 и ветку `feature/lc7.4-amvera-secrets` только после PASS нового CI. Прежний JSON поддержан для локальных запусков. Кодирование HEX1 не защищает секрет от прочтения.

## До подключения

1. Убедиться, что CI актуального SHA feature/lc7.4-amvera-secrets завершился успешно, проверить load.json и cloud-browser.json.
2. В проекте twi-center выбрать приложение (не PostgreSQL), тариф «Начальный» 500 МБ RAM для первого эксперимента. При превышении памяти остановить приложение, оценить load.json и перейти на больший тариф только после согласования. Один контейнер/одна реплика. На реальной Amvera память/CPU не проверены.
3. В разделе «Переменные» добавить LC_PILOT_DEMO со значением 1 и секретную LC_PILOT_USERS. Не помещать токены в Git, не отправлять их в чат и не скриншотить заполненное поле. Токен GitHub НЕ является токеном входа в TWI.

### Генерация тестовых токенов на Windows

Скачать `tools/twi-pilot-token-generator.html` из этой ветки и открыть локально в разрешённом браузере. Нажать «Создать токены», сохранить три индивидуальных токена в разрешённом защищённом хранилище и нажать «Копировать для Amvera». Вставить значение, начинающееся с HEX1, в LC_PILOT_USERS как секрет этапа «Запуск». Не добавлять кавычки. Очистить буфер после вставки. Не отправлять значение или индивидуальные токены в Git, чат, отчёт, скриншот. Вход — индивидуальный 64-символьный токен, а не значение HEX1 целиком. Генератор работает локально, с Web Crypto, без сети. При невозможности запуска или копирования остановиться, не ослаблять защиту Windows.

## Подключение и проверка

В «Репозиторий» выбрать shonentez-afk/Lean-Center, ветку feature/lc7.4-amvera-secrets. Подключение может автоматически запустить сборку и списания; выполнить только после команды владельца. В репозитории уже есть amvera.yml: Node.js 22, npm, дополнительная команда node tools/build_folder.mjs --cloud, scriptName server/main.mjs, порт 8080, persistenceMount /data. Сборка облачной версии не зависит от наличия .git; подлинность Stage43 проверяется по закреплённому Git blob SHA.

Дождаться статуса запуска. В «Домены» создать бесплатный HTTPS-домен по инструкции Amvera. Открыть /healthz: ожидается JSON ok:true, pilot:LC7.4.2. Затем открыть корень сайта, ввести индивидуальный токен editor1 и проверить Дашборд. Во втором независимом браузерном профиле войти editor2, создать разных учебных сотрудников; оба должны появиться после синхронизации. В viewer1 проверить чтение и запрет сохранения. В настройках нет издателя. Проверить импорт/редактирование демонстрационного СОП, скачивание JSON и XLSX. После испытания остановить приложение в панели Amvera, проверить баланс/статус. Не удалять проект/постоянное хранилище.

## Данные и резервирование

/data/lean-center-pilot/state.lcp — единый атомарный файл манифеста и настоящих SQLite-байтов; не открывать его как обычный .sqlite. previous.lcp — предыдущий подтверждённый снимок, документы — /data/lean-center-pilot/documents/<SHA-256>.json. Никакой WAL или второй процесс записи. В случае сбоя старый writer.lock НЕ удалять вслепую; сначала убедиться через панель/поддержку, что контейнер остановлен, скачать полный каталог, проверить копию, только потом разбирать блокировку. При отсутствии state.lcp в непустом каталоге (в том числе старый state.sqlite из LC7.4.0/1) инициализация запрещена. Старые экспериментальные файлы не преобразуются автоматически; до LC7.4.2 реальное развёртывание не подтверждено.

После остановки скачать всю папку /data/lean-center-pilot из Amvera либо использовать файловый экспорт платформы. Проверить резервирование локально в Linux с кодом той же версии и npm ci:
```sh
node server/maintenance.mjs backup /absolute/lean-center-pilot /absolute/backup-new
node server/maintenance.mjs restore-new /absolute/backup-new /absolute/restore-new
```
Папки назначения должны отсутствовать; восстановление в существующую базу запрещено. Проверяются независимый SHA-256 снимка и каждый исходник. Не откатывать работающую базу на старую публикацию без отдельной процедуры согласования: клиенты отвергнут откат. Хранить внешнюю резервную копию вне облака; previous.lcp — не замена внешнему бэкапу. При новом развёртывании проверить тот же ID базы, публикацию и документы после штатной остановки/старта. Аварийный SIGKILL и реальные гарантии блочного хранилища Amvera ещё не проверены.
