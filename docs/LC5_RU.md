Статус: разработка, НЕ принятая сборка. Основание: принятая LC4.4.1 (v10), согласованный пользователем единый этап LC5.1–LC5.8 и план из источника проекта «Продолжить разработку проекта.txt». ## Состав пакета
- LC5.1: 20 критериев RC1 (7+4+4+5) и рекомендации сохранены. Версия формы фиксируется в аудите. Ответы: да, нет, не наблюдалось, не применимо. Для двух последних — основание; незаполненное не равно нет.
- LC5.2: журнал, подробности и история версий, замечания, связи с инструктором, обучаемым, аудитором, операцией, редакцией СОП, фактом обучения. Исторические снимки не переписывать при изменении справочников.
- LC5.3: единые задачи по аудиту, СОП, оценке СОП, ФРВ, назначению обучения, отрицательной практической оценке, цели развития, самостоятельные корректирующие задачи. Ссылки на источники, ответственный, субъект, сроки, приоритет, факт выполнения и отдельная верификация.
- LC5.4: календарь и личные записи; планирование аудитов, общие сроки мероприятий, обучения и развития. Переобучение инструктора — из аудита его преподавания; повторное обучение обучаемого — из отдельной отрицательной практической оценки, не из аудита инструктора. Связь с подтверждённым последующим обучением, практикой/планом. Не присваивать квалификацию или допуск автоматически.
- LC5.5: показатели и детализация по версии методики, наблюдаемому знаменателю, повторным отклонениям, состояниям мероприятий; без выдуманного нормативного порога качества. Не смешивать версии. Учитывать факт и его контекст.
- LC5.6: карточка сотрудника и профиль наставника/связанные аудиты и задачи; сертификация показывает основания для ручной проверки, а не автоматическое нормативное решение.
- LC5.7: импорт базы RC1 v2/v3, пакета RC1 mobile v1, автономная HTML-форма LC5 и её собственный импорт. Сопоставление сотрудников явно, не создавать их из похожих ФИО; история исходных ID и методик, хеши, дедупликация и отклонение конфликтов. Дробные исторические значения и null сохранять отдельно. Дополнительные записи RC1 (старые мероприятия, каскады, журнал изменений, журнал мобильного обмена) сохраняются отдельным историческим архивом, не превращаются автоматически в действующие мероприятия, сроки или доказательства эффективности. Для активного исполнения требуется новая управляемая запись. Мобильная очередь сохраняется локально, повторный импорт не дублирует аудиты; не считать полноценной синхронизацией с подтверждением доставки.
- LC5.8: JS regression, Python smoke, сборка, браузерные сценарии на Windows/Linux. Публикация рабочего ZIP отключена до успешной проверки. Предыдущие прогоны промежуточных коммитов прошли JS/Python/сборку, но были отменены на браузерном этапе при новых коммитах. Run 45683906302: 71/72 на обеих ОС; причина — совпадение имени source у ссылок мероприятий с LC3 ссылками на содержимое. Исправление 0ef59e37a5a62d025262d5ef8877de21f3350b54: source_link, не ослабляя валидацию LC3. Не считать окончательно прошедшим CI до проверки именно этого или последующего кода.

## Методологическая карта M01–M15
Источник: baselines/twi-rc1/twi/docs/TWI_JI_LITERATURE_GAP_AUDIT_20261118_RU.md. Здесь классификация реализованных мер и открытых требований, не утверждение официального стандарта.
| ID | Что сделано / ограничение |
|---|---|
| M01 | Сохранена согласованная корпоративная форма 7+4+4+5; Get Ready To Instruct не следует смешивать с каноническим Prepare the Worker. Отдельная утверждённая аналитическая группировка и перекрёстная карта ещё не завершены. |
| M02 | Нет автоматически навязанных +30/+60–90. Новые даты L1 явные; старые каскады архивные. Политика интервалов и формы L2/L3 требуют согласования. |
| M03 | Четыре состояния, основания, полнота и наблюдаемый знаменатель. |
| M04 | Исполнение не равно эффективности; одинаковая операция, редакция, методика и инструктор, реальный последующий факт обучения; повторное отрицательное наблюдение исключает подтверждение. Из-за точности дат принимается только последующий день. Окна и число наблюдений не выдаются за норматив TWI. |
| M05 | Критичность отделена от процента, учитываются утверждённые флаги. Не назначать произвольно критические критерии RC1; порядок обязательной эскалации требуется согласовать с ОТ/производством. |
| M06 | Вопросы и рекомендации не изменены; контекст и заметки сохранены. Формальная карта JI и уточнённые наблюдаемые признаки остаются открыты. |
| M07 | Точные связи с операцией, версией СОП и фактом обучения; для старых данных без проверяемого контекста не выдумывать связь. |
| M08 | Сохранены отдельные план обучения, матрица навыков, проверка компетентности, допуск LC4; аудит не изменяет их автоматически. |
| M09 | L1 преподавания и практическая оценка обучаемого независимы. L2/L3 не моделируются как выдуманные утверждённые процедуры. |
| M10 | Примечания по критериям, аудитор, дата, версия и контекст. Отдельная калибровка оценщиков, прикрепление фото к наблюдениям и норматив доказательств не закрыты. |
| M11 | Версии, числители/знаменатели, повторяемость, отдельные критические отклонения, без эвристических порогов RC1 как официальных требований. Дополнительная аналитика после обучения и утверждённые внутренние индексы остаются открыты. |
| M12 | Обязательный результат исполнения, отдельный проверяющий, независимое подтверждение и состояния эффективности. |
| M13 | Стабильные ID, неизменные снимки записанных имён, журнал событий. |
| M14 | Legacy fractional score сохранён отдельно, не преобразован в «нет». |

### Исправление браузерной регрессии LC5
CI 45684368227: 72/72 JS, Python и сборка PASS на Windows/Linux; браузерные LC1–LC3 PASS, LC4/LC5 остановились при создании мероприятия со сроком сегодня. Причина: верхняя граница даты UTC+14 ошибочно использовалась как нижняя для планового срока. Исправлены обе формы (мероприятие и плановый аудит): UI проверяет локальную дату, ядро при воспроизведении UTC-событий допускает самую раннюю возможную календарную дату UTC−12. Верхняя граница наблюдений не изменена. Добавлен регрессионный тест пограничных часовых поясов, без отключения браузерного сценария.

CI 45685551248: 72/73 JS. Новый тест календарных границ ошибочно создавал два события одного назначения на одну дату; ограничение UNIQUE сработало корректно. Тестовые даты разделены с сохранением всех трёх пограничных сценариев. Добавлена отдельная проверка запрета дублей и понятное сообщение пользователю. Схема и защита от дублей неизменны.
