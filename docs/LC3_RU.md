# LC3.0 — библиотека СОП и ФРВ, кандидат
Основа: LC2.0 candidate (не принята пользователем); main остаётся LC1.3. Ветка feature/lc3-document-library.
## Интеграция
- Пин Stage43 HTML Git blob 5e35036ce243fed74ea018ac8eaf5f6c4a3c3e45. Исходная сборка и SOP-generanjr неизменны. При сборке создаётся производная редактора: изоляция localStorage/IndexedDB по session, отключение startup ping, CSP connect-src data: blob: (декодирование локальных фотографий; HTTP/HTTPS запрещены), адаптер postMessage с проверкой источника окна и токена. Старые кнопки сетевого хранения/публикации скрыты. Редактор открывается отдельным рабочим окном, не меняет исходный preview, механизм фотографий, разметку и экспорт Stage43. Не является полной перерисовкой редактора в новом стиле. Передача в центр требует подтверждения. При блокировке окон/неудачной передаче скачать JSON.
- СОП импортирует только portable schemaVersion=2 с проверенной внутренней SHA-256; сохраняет исходный JSON (TWI, оригиналы и отрисованные фото, разметка, остальные поля). Допустимые изображения JPEG/PNG/WebP/GIF data URLs; другие форматы требуют преобразования на стороне исходного редактора. FRV-1.2/1.3 импортируется как отдельное исследование; исходные метаданные/анализ сохранены, неполные измерения не считаются нулями. Дата наблюдения задаётся пользователем, а не выводится из даты импорта.
- В общей БД: document, document_revision, document_step, document_approval, frv_study, frv_measurement, attachment/attachment_link. Одно открытое состояние версии и одна действующая версия, новая версия не перезаписывает ранее утверждённую. Согласование: draft → review → approved → effective; return → draft; при введении следующей версии предыдущая superseded; withdraw с причиной, затем архивирование. Связь с действующей операцией обязательна для согласования. Ответственный выбирается вручную; это журнал делового решения, не цифровая подпись/авторизация. FRV final требует действующей операции и хотя бы одного полного цикла. TWI сохраняется в исходнике СОП, самостоятельная квалификация/назначения обучения — LC4.
- Принятая палитра LC1.3 и справочники LC2 сохранены. Код документа задаётся человеком, номер Stage43 сохраняется как исходный. Не смешивать номер версии исходника и номер версии Lean Center. Импорт из полного архива библиотеки Stage36 и автоматическое сопоставление legacy IDs/номеров нескольких версий пока не реализованы; импорт по одному JSON. Не считать первоначальный legacy статус «Опубликован» согласованием в новой системе.
## Файлы и безопасность данных
Хэш точного UTF-8 текста portable JSON — имя неизменяемого файла Documents/<sha256>.json в папке данных. В SQLite нет фото-байтов; есть ссылка/размер/MIME, краткая типизированная проекция и журнал. Исходник сначала сохраняется в локальный IndexedDB (отдельные ключи content:<sha>), затем атомарный пакет событий, контроль SHA и проекции при приёме. На сетевой диск файл записывается и проверяется до пакета и публикации. При отсутствии файла — отказ, без изменения базы. При чтении из сети локальное кэширование, offline-доступ к ранее загруженным исходникам. Старые исходники не удаляются автоматически, полная копия включает историю. На ручном обмене и backup при наличии исходников используется lean-content-bundle-v1; отсутствующий/повреждённый файл блокирует восстановление и публикацию. Прежние копии без документов поддерживаются.
Ограничения пилота: один исходник до 30 МБ, проекция до 2 МБ, 1000 шагов, 5000 наблюдений, пакет метаданных до 5 МБ/2000 событий, переносимый полный комплект до 150 МБ. Большие библиотеки: отдельное согласованное резервирование Database + Documents + Exchange, будущая оптимизация/очистка кэша и разбиение полной копии. Только доверенные исходники предприятия; хэш не доказывает авторство. Сохранение отдельного исходника не гарантирует принятие события; отказ может оставить безопасный orphan, не удалять вручную.
## Миграция и приёмка
Схема 004_lc3.sql — v4; читает v2/v3 после проверки оригинальных хэшей, пакеты старых справочников, не меняет прошлые события. При найденных ранее вручную созданных document/frv rows миграция останавливается до явного сопоставления. Старые LC1/LC2 не читают опубликованную v4. Резервирование перед обновлением; закрыть старые вкладки, каталог версии первым, index.html последним. CI проверяет Windows/Linux: регрессии LC1/2, доменные тесты, два клиента эмулированного файлового API, полный roundtrip Stage43 с фото, FRV и backup. Проверить фактический статус Actions. Не загружать рабочие файлы и ФИО. Реальная проверка LC2 и LC3, два ПК, права ACL и большой объём остаются открытыми.
